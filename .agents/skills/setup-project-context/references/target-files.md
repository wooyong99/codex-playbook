# 대상 파일

이 스킬은 아래 핵심 프로젝트 컨텍스트 문서 4개를 강제 초기화 대상으로 본다. 이미 채워진 문서도 호출 시 사용자 답변 기준으로 다시 쓴다.

## 1. [AGENTS.md](../../../../AGENTS.md)

현재 이 파일에서 채워야 하는 프로젝트 전용 플레이스홀더:

- `{프로젝트명}`
- `{비즈니스 목표 1}`
- `{비즈니스 목표 2}`
- `{비즈니스 목표 3}`

작성 규칙:

- 프로젝트명과 비즈니스 목표 섹션을 사용자 답변 기준으로 다시 쓴다.
- 공통 AI 작업 지침과 문서 맵 구조는 유지한다.
- 비즈니스 목표는 짧은 bullet point로 유지한다.

## 2. [docs/backend/README.md](../../../../docs/backend/README.md)

현재 이 파일에서 채워야 하는 프로젝트 전용 플레이스홀더:

- `{프로젝트명}`

작성 규칙:

- 프로젝트명 문장을 사용자 답변 기준으로 다시 쓴다.
- 기존 백엔드 탐색 구조, 아키텍처 링크, 정책/설계 문서 참조는 유지한다.

## 3. [docs/frontend/README.md](../../../../docs/frontend/README.md)

현재 이 파일에서 채워야 하는 프로젝트 전용 플레이스홀더:

- `{프로젝트명}`

작성 규칙:

- 프로젝트명 문장을 사용자 답변 기준으로 다시 쓴다.
- 기존 프론트엔드 탐색 구조, 컨벤션, 성능, UI/UX 섹션은 유지한다.

## 4. [docs/PRD.md](../../../../docs/PRD.md)

현재 이 파일에서 채워야 하는 프로젝트 전용 플레이스홀더:

- `{프로젝트명}`
- `{PRD 한 줄 요약}`
- `{배경 및 해결하려는 문제}`
- `{비즈니스 목표 목록}`
- `{핵심 성과 지표(KPI) 목록}`
- `{이번 범위에서 제외하는 항목}`
- `{사용자 유형}`
- `{인터페이스명}`
- `{진입점}`
- `{기능별 요구사항 목록}`
- `{성능, 보안, 가용성 등 비기능 요구사항}`
- `{기술적·비즈니스적 제약}`
- `{주요 마일스톤 및 일정}`

작성 규칙:

- PRD는 사용자 답변 기준으로 다시 쓴다.
- 사용자가 답하지 않은 항목은 임의로 채우지 않고 `미정` 또는 `확인 필요`로 표시한다.
- 프로젝트명과 비즈니스 목표는 `AGENTS.md`와 같은 값을 사용한다.
- PRD 형식은 기존 섹션 구조를 유지한다.

## 일관성 체크

- 네 파일에는 동일한 프로젝트명을 사용한다.
- `AGENTS.md`와 `docs/PRD.md`의 비즈니스 목표는 동일한 의미를 유지한다.
- 대상 파일에 더 이상 플레이스홀더가 없더라도 호출 시 사용자 답변 기준으로 다시 채운다.
