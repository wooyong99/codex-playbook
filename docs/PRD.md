# codex-playbook — Product Requirements Document

AI 에이전트가 대규모 실무 코드베이스에서 일관된 품질로 작업하도록 도구, 규칙, 지식, 검증 체계를 제공하는 프로젝트 플레이북.

---

## 배경 및 문제 정의

AI 에이전트는 코드 작성 속도를 높일 수 있지만, 프로젝트 맥락을 충분히 알지 못하면 설계 원칙 위반, 검증 누락, 문서 불일치, 과도한 변경 범위 같은 문제가 반복된다.

특히 20만~100만 라인 규모의 엔터프라이즈 코드베이스에서는 단일 프롬프트나 일반 코딩 규칙만으로 품질을 유지하기 어렵다. 에이전트가 읽어야 할 지식, 따라야 할 규칙, 남겨야 할 산출물, 수행해야 할 검증, 실패 시 복구 방식이 저장소 안에서 명확히 관리되어야 한다.

codex-playbook은 사람과 AI가 함께 읽고 실행할 수 있는 프로젝트 지식 시스템과 에이전트 작업 프로토콜을 제공한다.

---

## 목표

- AI 에이전트가 도구, 규칙, 지식, 검증을 같은 기준으로 사용하도록 작업 환경을 표준화한다.
- 대규모 코드베이스에서도 계획, 구현, 검토, 복구 흐름을 재현 가능하게 만든다.
- 사람과 AI가 공유하는 프로젝트 지식 시스템을 유지해 작업 품질 편차와 재작업 비용을 줄인다.

### 성공 지표

- 새 프로젝트 적용 시 핵심 플레이스홀더와 문서 맵 검증을 자동으로 통과한다.
- 대표 구현 작업에서 설계, 구현, 검토, 검증 산출물이 누락 없이 남는다.
- 문서 링크, 규칙 ID, handoff artifact, checkpoint artifact 검증을 CI에서 반복 실행할 수 있다.
- 20만~100만 라인 코드베이스 적용 시 전체 정독 없이 census, 샘플링, confidence report 기반 문서화 계획을 만들 수 있다.
- 대표 평가 시나리오에서 85점 이상, blocker 0건을 pass 기준으로 사용할 수 있다.

### 범위 외 (Non-Goals)

- 특정 회사의 전체 개발 프로세스나 조직 운영 방식을 대체하지 않는다.
- 모든 기술 스택에 대한 완성된 규칙 세트를 기본 제공하지 않는다.
- 에이전트 출력의 업무적 정답성을 자동으로 보증하지 않는다.
- 제품별 도메인 지식을 추측해서 채우지 않는다.

## 기능 요구사항

- 프로젝트 최상위 작업 지침을 `AGENTS.md`에서 제공한다.
- 백엔드와 프론트엔드 지식 시스템을 `docs/backend`, `docs/frontend`로 분리해 관리한다.
- 구현 작업은 요구사항 분석, 설계, 코드 작성, 아키텍처 검토, 검증 보고 흐름을 따른다.
- 대규모 코드베이스 분석은 전체 정독이 아니라 census, 우선순위화, 제한 샘플링, confidence report 방식으로 수행한다.
- 에이전트 간 handoff artifact와 checkpoint artifact를 파일로 남겨 재개 가능성을 보장한다.
- 새 프로젝트 적용 시 플레이스홀더, 문서 링크, 문서 맵, 규칙 검증을 수행할 수 있어야 한다.
- 규칙 위반은 안정적인 Rule ID와 severity를 포함해 보고되어야 한다.
- 평가 시나리오와 scorecard를 제공해 플레이북 품질을 반복 측정할 수 있어야 한다.

---

## 비기능 요구사항

- 대규모 저장소에서도 불필요한 전체 파일 정독을 피하고 탐색 예산을 명시한다.
- 규칙과 문서는 단일 출처를 가져야 하며, 중복 원문을 최소화한다.
- 검증 스크립트는 로컬과 CI에서 동일하게 실행 가능해야 한다.
- 에이전트 산출물은 재현 가능한 파일 경로와 구조화된 스키마를 가져야 한다.
- 민감 정보, 개인 정보, 운영 비밀 값을 문서나 로그에 임의로 남기지 않아야 한다.

---

## 제약 사항

- 이 저장소는 템플릿이므로 실제 프로젝트 적용 시 도메인, 기술 스택, 실행 명령은 반드시 치환해야 한다.
- AI 에이전트는 문서에 없는 프로젝트 사실을 임의로 확정하지 않아야 한다.
- 검토 자동화는 문서 준수 여부를 돕지만, 사람의 코드 리뷰와 운영 판단을 완전히 대체하지 않는다.
- 대규모 코드베이스에서는 first pass 문서화 범위와 신뢰도를 명시하고 미분석 영역을 backlog로 남긴다.

---

## 타임라인

- M1: 프로젝트 정체성, PRD, 핵심 문서 플레이스홀더 확정
- M2: 깨진 링크와 잘못된 참조 정리
- M3: 플레이북 검증 스크립트와 기본 저장소 위생 추가
- M4: 규칙 ID와 metadata 체계 도입
- M5: 프론트엔드, 문서, 보안 검토 경로 확장
- M6: 특정 도메인 예시 격리와 템플릿 중립화
- M7: 에이전트 평가 suite 초안 추가
